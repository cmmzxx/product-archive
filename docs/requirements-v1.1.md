## 一、评审结论与本次修订

V1.0 的总体方向合理：先交付独立运行的只读浏览程序，再引入 CAD 操作，可以降低 TopSolid SDK 与桌面运行时耦合造成的实施风险。

正式开发前最需要消除的歧义如下。

| 优先级 | V1.0 中的缺口 | V1.1 处理方式 |
| --- | --- | --- |
| P0 | “TopSolid 支持自定义菜单启动外部程序”尚未针对目标版本验证 | 增加最小启动验证；不预先承诺具体配置文件、命令或菜单层级 |
| P0 | 私有化 API 版本、认证、字段和图纸关联方式未明确 | 增加接口契约与字段映射确认表；先支持实际存在的一种数据结构 |
| P0 | “只读密钥”与实际数据可见范围的关系不明确 | 区分服务身份权限与设计人员身份；明确桌面端凭据保护边界 |
| P0 | 关联字段可能只返回摘要或部分记录 | 明确关联记录分页、完整性提示及多附件展开规则 |
| P1 | 搜索、排序、刷新、选中保留规则不完整 | 增加确定的默认交互行为及接口能力核验要求 |
| P1 | 仅提及避免旧图纸覆盖，未覆盖搜索、错误和加载状态 | 产品与图纸请求分别实施取消和响应有效性检查 |
| P1 | 验收项以功能描述为主，缺少边界场景 | 补充并发切换、权限异常、部分加载、缺失字段和发布包验收 |
| P1 | 现代 .NET LTS 未明确版本 | 建议采用 .NET 10 LTS；补充 Mac 与 Windows 的验证边界 |

P0 项是对应真实环境联调或集成验收的前置条件，不妨碍先完成工程、界面和脱敏样例开发。

## 二、项目目标与范围

### 2.1 背景与用户

设计人员使用 TopSolid 7 进行设计，产品与相关图纸资料由明道云私有化部署管理。本项目让设计人员在独立桌面窗口中查询产品并查看关联图纸元数据，减少工作过程中的网页切换。

### 2.2 第一阶段目标

1. WPF 程序能够在 Windows 独立启动。
2. 从指定的真实产品工作表查询产品，支持搜索、服务端分页和刷新。
3. 单选产品后，按真实数据关系读取关联图纸或附件元数据。
4. 正确处理加载、空数据、错误及快速切换请求。
5. 经目标版本验证后，从 TopSolid 自定义入口启动程序。

第一阶段仅查询业务数据。查询接口即使采用 HTTP POST，也可以属于只读操作；判断依据是业务语义与服务端行为，不能只依据 HTTP 方法。

### 2.3 第一阶段不包含

- 下载、预览或解析图纸文件内容，包括为了识别格式、大小而访问附件文件流。
- 图纸业务选择，以及打开、导入、编辑、保存、导出和上传操作。
- TopSolid Automation SDK 调用、PDM 签入签出和 CAD 编辑锁。
- 图纸同步、版本写入、冲突处理、上传重试和业务审计记录写入。
- TopSolid 原生停靠面板、DLL 注入和内部程序修改。
- 新建或调整明道云工作表、字段、业务记录和业务工作流。
- 自动更新、完整用户登录系统和离线业务数据库。

如元数据无法完整取得，应显示缺失或加载失败状态，不以下载附件补足信息。运行日志与本地配置属于必要的本地文件，不属于业务数据写入。

## 三、技术与运行环境

### 3.1 技术基线

| 模块 | 方案 |
| --- | --- |
| CAD 软件 | TopSolid 7；准确版本、补丁号和位数待核验 |
| 语言与 UI | C#、WPF、MVVM |
| 第一阶段运行时 | 建议 .NET 10 LTS；Desktop 使用 `net10.0-windows` |
| 共享业务层 | Core、Infrastructure 优先使用 `net10.0`，避免依赖 WPF 或 TopSolid SDK |
| 开发系统 | macOS，VS Code 与 .NET SDK |
| 编译与调试基准 | 目标 Windows 环境及支持所选 SDK 的 Visual Studio / Build Tools |
| 数据交互 | 私有部署实际支持的明道云 API，通过 HTTPS 访问 |
| 代码管理 | Git，不提交真实凭据与敏感接口样本 |
| 第一阶段集成 | TopSolid 入口启动独立 EXE，具体方法经目标版本验证 |
| 第二阶段集成 | 依据实际 TopSolid SDK 决定运行时及进程边界 |

截至本文日期，.NET 10 为在支持期内的 LTS，支持至 2028-11-14；.NET 8 已于 2026-11-10 结束支持，不建议作为新项目默认基线。[S1]

### 3.2 Mac 与 Windows 的职责

- 按当前项目约定，Mac 只编写源代码与测试代码，不安装 .NET SDK、不还原依赖、不编译或执行测试。
- Windows：完成工具链安装、依赖还原、所有构建与测试、WPF 运行、数据绑定、布局、发布包和 TopSolid 集成验证。
- 非 Windows 系统在技术上可以启用 Windows 目标构建 [S2]，但本项目不使用该开发方式。

目标 Windows 版本与架构须同时满足所选 .NET 和实际 TopSolid 版本要求。建议先以设计电脑实际采用的 x64 环境为交付目标，不默认承诺 ARM64 或多个 TopSolid 版本兼容。

### 3.3 TopSolid 启动方式的验证

正式承诺菜单集成前，先用最小外部程序在实际设计电脑验证：

1. 获取 TopSolid 完整版本、授权环境及对应官方帮助资料。
2. 确认该版本是否支持从预期入口启动外部 EXE，以及配置权限和分发方式。
3. 验证含空格的安装路径、工作目录及启动参数处理。
4. 验证启动、关闭外部程序均不影响 TopSolid 当前文档与正常运行。
5. 保存验证记录，并在交付说明中给出可复现的配置步骤。

“明道云集成 → 产品图纸管理”是期望的入口名称与层级，不作为未经验证的 TopSolid 能力声明。若目标版本不支持该方式，记录限制后再确定替代入口；不能自行将 SDK 扩展或原生面板纳入第一阶段。

## 四、真实接口与字段映射

### 4.1 接口联调前必须取得的信息

| 类别 | 必需信息 | 验证结果 |
| --- | --- | --- |
| 环境 | 私有部署地址、API 基路径与版本、VPN/代理及证书要求 | 待核验 |
| 认证 | 认证方式、凭据来源、有效期、权限范围 | 待核验 |
| 产品 | 应用 ID、产品工作表 ID、记录 ID 的真实返回位置 | 待核验 |
| 产品字段 | 名称字段 ID；编码、系列、类别字段 ID（如有）及类型 | 待核验 |
| 查询 | 字段筛选、OR 条件、排序、页码或游标、每页上限 | 待核验 |
| 返回结果 | 成功与业务错误结构、总数或下一页判断方式 | 待核验 |
| 图纸关系 | 直接附件 / 产品关联图纸表 / 图纸表反向关联产品 | 待核验 |
| 图纸字段 | 关联字段、目标工作表、附件字段及名称、版本等可选字段 | 待核验 |
| 完整性 | 关联摘要是否截断、详情和关联记录如何分页、字段可见性 | 待核验 |

以该私有部署的实际文档与响应为准，不假定与公有云或其他版本接口完全一致，也不把用于管理明道云的 MCP 工具直接当作桌面程序部署依赖。

联调资料至少包含经过脱敏的产品列表、产品详情、附件、关联记录和失败响应样例；按实际采用的数据结构提供。凭据通过安全渠道单独交付，不写进需求文档或 Git。

### 4.2 产品字段规则

| 统一字段 | 来源与规则 |
| --- | --- |
| RecordId | 明道云记录 ID，必需；作为选中、关联查询和去重依据 |
| Name | 配置指定的产品名称字段；字段映射必需，个别空值显示“未命名产品” |
| Code | 产品编码字段，可选；不假定唯一，不代替记录 ID |
| Series | 产品系列字段，可选 |
| Category | 产品类别字段，可选 |

未配置的可选字段不显示对应列；已配置字段的个别空值显示“—”。选项、关联值等须按确认后的字段类型转换为可读文本，不能直接显示原始 JSON。

必需字段配置错误、字段被删除或响应结构无法识别时，显示配置或接口错误；不能将解析失败静默转换为“没有产品”。

### 4.3 图纸来源与第一阶段实施范围

**A. 产品直接包含附件字段。** 选中产品后读取产品详情中的完整附件元数据。只有确认列表响应已经包含完整数据且刷新语义一致时，才复用列表数据。

**B. 产品通过关联字段连接独立图纸表。** 按实际关联接口读取记录，不将关联字段中的摘要数组视为完整列表。若图纸表反向关联产品，则按产品记录 ID 在服务端筛选。

先确认真实结构，再实现实际使用的一种方式。只有现有业务确实同时存在多种来源时，才增加组合展示，不要求为假设场景同时开发全部适配器。不能通过“产品名称相同”或“编码看起来一致”推断关联关系。

### 4.4 图纸列表的粒度与字段语义

默认按“每个附件一行”展示；一条图纸记录包含多个附件时展开多行。关联图纸记录没有附件但存在有效图纸业务信息时，可显示一条元数据记录，文件格式和大小保持缺失，不能伪装为已有文件。

| 展示字段 | 规则 |
| --- | --- |
| 名称 | 有独立图纸名称时优先展示；同时保留附件原文件名以区分多附件；否则使用文件名，再缺失则显示“未命名图纸” |
| 格式 | 使用确认有效的格式元数据；缺失时可从文件名扩展名推导，仅用于展示；无法识别时显示“未知” |
| 文件大小 | 仅使用附件元数据中的字节数；缺失显示“—”，不能当作 0；显示单位使用 B、KiB、MiB 等 |
| 版本 | 使用业务版本字段，原样作为文本展示；缺失显示“—”，不自动生成 V1 或推导版本 |
| 更新时间 | 优先显示可确认含义的附件更新时间；若仅有图纸记录修改时间，应标明“记录更新时间” |
| 来源 | 标明产品附件或关联图纸记录；多来源时保留可区分来源的显示信息 |
| 内部标识 | 保留来源工作表、记录 ID、附件 ID（接口提供时），用于识别条目，不依赖名称作为唯一键 |

不能把产品记录修改时间称为附件更新时间。无时区时间值需先确认部署时区；有明确时区时统一按当前 Windows 时区显示，并在界面说明时区。时间与版本来源无法确认时保留缺失，不猜测。

附件 URL 可能具有时效或包含签名。第一阶段不依赖 URL 下载、探测文件或打开浏览器，不将其当作稳定文件标识，也不写入日志。

### 4.5 配置管理

环境地址、工作表、字段映射、关联方式、排序和分页参数集中配置。真实字段 ID 不散落在 ViewModel、XAML 或多个 API 方法中。

普通配置文件只存非秘密设置及凭据引用。启动时校验必需项；存在可安全验证字段结构的只读接口时，在首次连接或配置验证过程中核验。第一阶段可由管理员维护配置文件，不要求新增完整设置界面。

## 五、第一阶段功能与交互规则

本节数值与交互选择为建议默认基线，接口联调发现能力限制时应明确登记调整，不能静默降低功能。

### 5.1 产品查询（FR-P）

| 编号 | 要求 |
| --- | --- |
| FR-P01 | 配置有效时，启动后自动查询第一页；不自动选择第一条产品 |
| FR-P02 | 单个搜索框按“名称包含关键词 OR 编码包含关键词”查询；编码未配置时仅搜索名称，并相应调整提示文本 |
| FR-P03 | 去除关键词首尾空白；空关键词恢复无搜索条件查询；大小写及中文匹配按真实服务端规则验证 |
| FR-P04 | 输入停顿 400 ms 后搜索；Enter 立即执行并取消待执行的防抖任务；相同条件不重复自动发送请求 |
| FR-P05 | 搜索采用服务端过滤，不得仅过滤当前页；若接口不支持目标匹配规则，须先确认可替代规则 |
| FR-P06 | 默认每页 50 条，受实际接口上限约束；更换搜索条件后回到第一页 |
| FR-P07 | 提供上一页、下一页和当前页状态；只有总数可靠可得时显示总数、总页数或末页入口 |
| FR-P08 | 固定服务端排序，建议名称升序、记录 ID 作为次级排序；是否支持该组合须核验；不以当前页本地排序冒充全局排序 |
| FR-P09 | 手动刷新保持关键词和页码；若已确认该页因数据减少而不存在，则返回有效页；不为此扫描全部页面 |
| FR-P10 | 展示查询中、无匹配产品、加载失败等独立状态，并支持失败后重试 |

没有总数时，下一页判断优先使用接口游标或 `hasMore` 等能力；若只能根据满页推断，允许最后出现一个空页，但不得显示未经证实的精确总数。具体协议在接口契约中固定。

### 5.2 产品选择与刷新（FR-S）

1. 仅允许选中一个产品，以记录 ID 保存选中状态。
2. 选择产品后，右侧立即显示该产品信息，清除上一产品的图纸和错误，再加载当前产品图纸。
3. 搜索或翻页请求实际发起时，清除产品选择及右侧内容；新结果返回后不自动选择产品。
4. 手动刷新前记录当前选中 ID；刷新成功后仅在该记录仍位于当前页时恢复选择，并重新查询图纸，否则保持未选择。
5. 列表加载失败时显示错误，不将旧产品或旧图纸作为当前成功结果展示。
6. 产品已删除、不可访问或详情获取失败时，明确提示；不能当作“该产品无图纸”。

### 5.3 图纸查询（FR-D）

1. 图纸列表只在选择产品后按需查询，不随产品列表逐项预加载。
2. 关联查询默认每批 50 条记录，按已确认的稳定服务端顺序读取；多附件展开后的显示行数可以超过 50 行。超过一批时提供“加载更多”，直至真实关系中的记录全部读完。
3. 对直接附件数组，可在完整取得元数据后按需分批显示；这不意味着允许下载文件内容。
4. 明确展示“已加载 X 条”；只有可靠总数存在时才展示总条数。记录未全部读取时不能显示“全部图纸”。
5. 多附件展开后，图纸展示行数可能大于关联记录数；计数标签应区分“图纸条目”和“关联记录”。
6. 首批失败时展示错误及重试；后续批次失败时保留已加载条目，明确显示“尚未加载完整”并允许重试失败批次。
7. 同一产品一次只执行一个后续批次请求，避免重复点击造成重复读取。批次重试时依据来源记录与附件标识避免重复追加。无稳定附件 ID 时，按已核验的响应位置或来源元数据在本次加载内识别，不能声称跨版本身份稳定。
8. 提供刷新当前产品图纸的方式；刷新后重新从首批读取，第一阶段默认不增加数据缓存。
9. 成功且确认没有可见关联数据时显示“暂无可见图纸”。权限或解析失败必须显示相应错误。

“全部”始终限定为当前 API 身份有权限读取的数据。若接口对无权限数据直接返回空集，客户端不能自行推断是否确实没有图纸，须在权限确认和验收中说明这一限制。

### 5.4 异步与过期响应（FR-R）

- 产品查询、图纸查询分别维护请求有效性；新请求发起时取消前一同类请求。
- 取消只是减少无效工作。即使接口忽略取消，响应到达时也必须核验当前请求版本，并核对查询条件或所选产品 ID，确认仍有效后才更新界面。仅比较产品 ID 不足以处理 A → B → A 或同产品重复刷新的情况。
- 有效性检查同时覆盖数据、错误提示、计数和加载状态，避免旧请求的异常或结束事件覆盖新请求状态。
- 图纸“加载更多”也属于对应产品的请求上下文，切换产品后不得追加旧产品数据。
- 用户主动切换导致的取消不显示为接口故障；窗口关闭后取消请求并停止界面更新。

## 六、界面与状态

### 6.1 布局

采用左右两栏，支持调整宽度。

| 区域 | 内容 |
| --- | --- |
| 顶部 | 应用名称、当前环境的非敏感标识；不展示密钥 |
| 左侧 | 搜索框、刷新按钮、产品表格、分页和查询状态 |
| 右侧顶部 | 当前产品名称、编码及可用的基本信息，图纸刷新入口 |
| 右侧主体 | 只读图纸表格、已加载数量、加载更多及状态提示 |
| 底部或对应区域 | 可理解的错误摘要、重试入口；必要时显示诊断编号 |

列随实际字段显示。长名称应可完整查看；在目标设计电脑的常用分辨率与 100%、150% DPI 下，不应遮挡搜索、分页和重试等关键操作。

第一阶段不提供图纸操作按钮，图纸列表不承担第二阶段的业务选择功能。界面以中文为主，错误信息不得直接显示完整异常堆栈。

### 6.2 状态区分

| 场景 | 展示行为 |
| --- | --- |
| 未选择产品 | 右侧提示“请选择产品查看关联图纸” |
| 产品查询中 | 左侧显示加载状态，不阻塞窗口移动和关闭 |
| 无匹配产品 | 左侧显示“未找到匹配产品”，允许更改关键词 |
| 图纸查询中 | 右侧显示当前产品及加载状态，不显示上一产品图纸 |
| 无可见图纸 | 成功状态下显示“暂无可见图纸” |
| 查询失败 | 对应区域显示错误与重试入口，不能使用空数据文案 |
| 部分已加载 | 保留已加载数据，显示剩余加载或失败状态 |
| 配置无效 | 提示管理员检查具体配置类别，不发起明显无效的业务请求 |

同一查询上下文中的“成功但为空”“权限失败”“加载失败”必须有不同状态，不能仅用一个空集合表达。

## 七、API、异常与权限

### 7.1 只读接口边界

第一阶段允许的调用范围为：产品列表、必要的产品详情、关联图纸列表或详情，以及确有必要的只读字段结构查询。

不调用记录增删改、附件上传、工作流触发、PDM 操作或可能改变业务状态的链接生成接口。任何接口是否只读，须结合实际文档确认。程序正常运行产生的服务端访问日志不属于业务数据修改。

若列表已返回所需的完整图纸信息，不重复请求详情；若关联接口支持批量获取，优先使用，以免对每条产品或图纸产生不必要的详情请求。不得为弥补缺少关联筛选能力而扫描整个图纸工作表。

### 7.2 HTTP 行为

| 项目 | 建议默认规则 |
| --- | --- |
| 异步 | 所有网络请求异步执行，传递取消信号，不阻塞 UI 线程 |
| 超时 | 单次 HTTP 请求 30 秒，可按内网环境调整；对重试设置总耗时上限，避免无限等待 |
| 连接管理 | 复用 HttpClient 或等效连接管理，不为每条记录创建独立连接池 |
| 短暂故障 | 经确认幂等的只读查询，对连接中断、502/503/504 等最多自动重试 1 次，并短暂退避 |
| 限流 | 识别 429 及 Retry-After；超过允许等待时间时提示稍后重试，不持续发送请求 |
| 不自动重试 | 认证或权限错误、配置错误、业务错误、数据结构不兼容、用户主动取消 |
| 响应判断 | 同时检查 HTTP 状态和响应中的业务成功标志；HTTP 200 不等于业务成功 |
| TLS | 校验证书；内部 CA 通过受信任证书配置解决，不关闭证书验证 |

具体状态码、业务错误码和退避行为以实际接口契约确认。分页读取不能因为其中一批失败而反复重读已经成功的所有页面。

### 7.3 错误分类与提示

| 情况 | 用户提示方向 | 处理 |
| --- | --- | --- |
| 配置缺失或字段无效 | 配置不完整，请联系管理员检查指定配置类别 | 修复后重试，不伪装为空数据 |
| 网络不可达、DNS、代理错误 | 无法连接明道云，请检查网络或 VPN | 可手动重试 |
| 超时 | 请求超时，请稍后重试 | 保持程序可操作 |
| 认证失败或凭据失效 | 连接认证失败，请联系管理员更新凭据 | 不循环重试 |
| 无数据权限 | 当前连接身份无权读取所需数据 | 区分产品与图纸查询失败 |
| 记录不存在或不可访问 | 该产品或图纸已不存在，或当前身份不可访问 | 建议刷新产品数据；不笼统归为无图纸 |
| 限流或服务暂不可用 | 服务繁忙，请稍后重试 | 有限重试或展示等待提示 |
| 响应解析或字段类型异常 | 返回数据与配置不一致，请联系管理员 | 记录脱敏诊断信息 |

如接口无法区分“已删除”与“无权限”，使用兼容这两种情况的提示，不自行断言记录已删除。

### 7.4 凭据与数据可见范围

1. 不硬编码密钥，不将真实密钥放入安装包、普通配置、源代码、命令行参数或日志。
2. 开发期可使用本机环境变量或本机秘密存储；不能将开发用秘密文件提交到 Git。
3. 正式部署优先使用 Windows 凭据管理器或受当前用户保护的 DPAPI 存储，并明确凭据初始化、更换和撤销步骤。读取权限须与实际运行账户一致。
4. Windows 本地秘密存储主要保护静态存储；运行时可使用凭据的终端用户仍可能提取凭据，不能据此承诺应用级密钥绝对安全。
5. 第一阶段使用最小范围、只读的连接身份。必须由管理员确认该身份能看到哪些应用、工作表、记录和附件字段。
6. 应用级凭据通常代表服务身份，不能默认等同于当前设计人员在明道云网页中的个人权限。实际行为以私有部署认证机制验证。
7. 若使用统一服务身份，必须确认所有目标设计人员均被允许访问该身份可读的数据。若不满足，应先确定受支持的按用户授权方式或服务端代理，再进行真实数据分发。

不因凭据接入直接扩展完整登录系统。认证方式与权限范围的选择属于真实联调前的明确决策，不是开发者可以隐含假定的条件。

### 7.5 日志

- 记录时间、应用版本、请求操作类别、耗时、结果、错误类别和必要诊断编号。
- 不记录凭据、认证头、带签名的附件 URL、完整请求/响应载荷或完整异常敏感内容。
- 本地日志按大小或日期滚动，设置保留上限；建议保留最近 14 天且总量不超过 100 MiB。
- 日志写入失败不应导致程序退出；正常业务失败应能通过界面反馈。
- 日志位置和收集方式写入交付说明。必要的未处理异常应记录诊断信息；不能吞掉未知异常后继续使用可能损坏的状态。

## 八、架构与工程组织

### 8.1 第一阶段架构

```text
TopSolid 7（经验证的外部程序启动入口）
    │
    ▼
Desktop / WPF Views
    │ 数据绑定、命令
    ▼
ViewModels
    │ 通过 Core 中的服务接口
    ▼
Infrastructure / Mingdao API Client
    │ HTTPS，只读查询
    ▼
明道云私有部署：产品表、附件、实际存在的关联图纸表
```

WPF 后置代码只处理必要的窗口或视图行为。搜索、分页、选择和异步状态在 ViewModel 中组织；HTTP、认证和响应映射在 Infrastructure 中实现。

### 8.2 建议项目结构

```text
TopSolidMingdao/
├── src/
│   ├── TopSolidMingdao.Desktop/
│   │   ├── App.xaml
│   │   ├── MainWindow.xaml
│   │   ├── Views/
│   │   └── ViewModels/
│   ├── TopSolidMingdao.Core/
│   │   ├── Models/
│   │   └── Interfaces/
│   └── TopSolidMingdao.Infrastructure/
│       └── Mingdao/
├── tests/
│   └── TopSolidMingdao.Tests/
├── docs/
├── README.md
└── global.json
```

- Core 定义产品、图纸条目、查询条件、分页结果及必要服务接口，不依赖 WPF、HTTP DTO 或 TopSolid 类型。
- Infrastructure 负责私有部署响应 DTO、字段映射、认证、错误转换与 API 客户端。
- Desktop 负责界面、命令、选中状态、请求取消及有效性检查。
- 应用启动处完成配置和依赖装配；以最小需要选用库，不强制引入复杂框架。
- 工程建立时固定可用 SDK 版本；没有 API 总数时，分页结果允许总数缺失。
- 产品分页结果与图纸分页结果都需要表达“是否还能继续读取”；服务失败必须能与成功空结果区分。

第一阶段只在文档中保留 CAD Bridge 的模块边界，不要求新建空项目、空 SDK 接口或进程通信框架。第二阶段确认 SDK 能力后再建立对应实现。

### 8.3 测试边界

跨平台自动化测试重点覆盖真实风险：字段映射、多附件展开、缺失元数据、分页与业务错误解析、认证/超时分类，以及过期响应不能覆盖当前状态。

业务层保持与 WPF 分离，但本项目当前约定所有测试均在 Windows 执行。ViewModel 测试随 Windows 测试工程运行，不为在 Mac 运行测试而增加额外项目。WPF 绑定、布局和实际线程行为仍需 Windows 验证。不为简单属性或转发代码编写仅复述实现的测试。

脱敏响应样例用于重复验证映射逻辑；真实凭据与真实环境联调作为独立验证，不将样例测试通过视为真实接入完成。

## 九、性能、稳定性与发布

### 9.1 第一阶段性能要求

1. 产品列表只按当前页请求，不一次性拉取全部产品。
2. 图纸仅在选择产品后加载；大量关联记录可以继续读取，不在 UI 线程批量执行网络请求。
3. 搜索遵守防抖与取消规则，分页或选择操作不能留下无上限的后台请求。
4. 加载期间窗口能够正常移动、调整和关闭；不使用同步等待网络的方式阻塞 UI。
5. 首阶段不默认引入缓存；如实测确有必要，应补充缓存键、时效和刷新失效规则。

真实接口延迟、数据规模和网络条件尚不明确，不承诺无依据的端到端响应时间。试运行需记录产品规模、典型图纸数量、网络条件与查询耗时，双方再确定是否需要增加量化性能验收门槛。

### 9.2 稳定性

可预期的 API、网络和数据错误不得导致程序退出；应反馈可理解的原因和可行的重试操作。窗口关闭要取消后台读取并释放资源，不影响 TopSolid 进程或当前文档。

建议第一阶段允许多个独立程序实例，不增加单实例通信机制；每个实例独立管理查询状态。若试运行要求重复点击入口时激活已有窗口，再明确作为交互增强需求。

### 9.3 发布与分发

建议首版采用 `win-x64` 自包含文件夹发布，便于设计电脑离线分发，减少运行时预装依赖；是否采用该方式需根据目标环境确认。自包含发布的 .NET 安全补丁随应用更新维护。

若改用依赖框架的发布方式，必须注明目标电脑需要安装对应的 .NET Desktop Runtime，而非仅写“.NET Runtime”。

发布包至少包含：

- 可独立启动的程序及其依赖。
- 不含真实秘密的配置示例与字段映射说明。
- 凭据初始化、更换、撤销与故障排查说明。
- 经实际版本验证的 TopSolid 入口配置与移除步骤。
- 应用版本、构建信息、运行环境要求及日志位置。

安装目录与当前工作目录不能混用。程序应能从不同工作目录启动；本地配置、秘密存储和日志使用明确的可写位置，不要求以管理员身份运行。升级不得把真实凭据打包或覆盖丢失。

第一阶段可使用人工分发与回退版本，不要求自动更新。TopSolid 菜单路径需与安装位置保持一致。

## 十、第二阶段规划与进入条件

第二阶段继续复用产品查询和图纸浏览能力，增加图纸选择、打开或导入、保存、同步状态等操作。

| 图纸类型 | 规划方向；均需实测确认 |
| --- | --- |
| TopSolid PDM 原生文档 | 使用有效的 PDM 标识定位与打开；不能当作普通附件路径处理 |
| TopPkg | 下载并按目标版本能力导入 PDM |
| DWG / DXF | 下载后使用对应版本支持的导入器，验证许可与导入选项 |
| PDF / 图片 | 按业务需要预览；不作为可编辑 CAD 源文件处理 |
| 其他格式 | 明确提示不支持或人工处理 |

进入第二阶段前必须完成：

1. 确认实际 TopSolid SDK 版本、支持的运行时、位数、授权和连接方式。[S3]
2. 用真实样例验证各文件类型的打开、导入、导出和 PDM 行为，不能只根据扩展名承诺能力。
3. 确定原生 PDM 文档与附件文件的身份映射、版本来源和同步目标。
4. 确定冲突检测依据、历史保留、失败恢复及同步权限，避免简单覆盖历史文件。
5. 若 SDK 与 WPF 运行时不兼容，再采用独立 C# 进程的 CAD Bridge，并设计必要的进程通信。

第二阶段这些条件不转化为第一阶段的 SDK、下载或上传任务，也不通过提前加入大量预留字段解决尚未明确的同步问题。

## 十二、第一阶段验收用例

建议在代表性 Windows 设计电脑与真实明道云环境执行。权限异常、超时和过期响应等难以稳定触发的场景可使用可控测试环境验证，并记录验证方式；不能因此省略真实环境主流程。

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| AC-01 | 从发布目录直接启动 | 按约定发布模式可运行，显示明确环境与初始状态 |
| AC-02 | 使用目标只读身份连接真实环境 | 读取真实产品，字段映射正确，无认证信息泄露 |
| AC-03 | 搜索名称与编码 | 按确认规则进行服务端搜索，能命中不在原当前页的记录；无编码字段时按确认范围验收 |
| AC-04 | 连续输入后停顿、按 Enter | 防抖有效，Enter 即时搜索，不重复执行待发起搜索 |
| AC-05 | 产品数据超过一页，连续翻页 | 请求按页发起；静态测试数据下，无因随机排序造成的重复或遗漏；未知总数不显示虚假页数 |
| AC-06 | 选择产品、换页、搜索、刷新 | 单选状态与右侧一致；恢复或清除选择符合第 5.2 节 |
| AC-07 | 查询真实直接附件或关联图纸 | 按已确认的数据结构正确展示，产品与图纸按记录 ID 关联 |
| AC-08 | 一条图纸记录有多个附件 | 每个附件分别展示，名称、文件名、来源和条目计数可区分 |
| AC-09 | 关联记录数超过接口一页，或关联摘要被截断 | 可以继续读取至完整集合；未读完时不显示全部；展开附件后的计数语义正确 |
| AC-10 | 图纸确实为空 | 成功读取后显示“暂无可见图纸”，不出现错误堆栈 |
| AC-11 | 缺少大小、版本、格式或时间 | 按规则显示缺失或未知，不伪造 0、V1、文件时间，不发起文件探测 |
| AC-12 | A → B、A → B → A 及同产品刷新，旧请求延迟成功或失败 | 最终数据、错误和加载状态始终对应最后一次有效请求；仅产品 ID 相同的旧响应也不能覆盖新结果 |
| AC-13 | 连续变更搜索条件，旧搜索延迟返回 | 只展示最后有效查询；旧错误和结束事件不改变新请求状态 |
| AC-14 | 加载更多后立即切换产品 | 旧产品的后续图纸不能追加到新产品 |
| AC-15 | 后续图纸批次失败后重试 | 保留已加载条目并显示未完整状态；恢复后无重复追加 |
| AC-16 | 网络断开、超时、限流、服务器暂时故障 | 提示可理解、重试有限、窗口可操作，程序不因这些异常退出 |
| AC-17 | 凭据失效、无权限、记录不存在 | 与空数据状态区分，不能循环重试；提示不暴露秘密 |
| AC-18 | HTTP 成功但业务失败，或返回结构异常 | 正确识别失败，不把解析异常当作无产品或无图纸 |
| AC-19 | 字段配置错误、可选字段为空、中文及长名称 | 必需配置错误可定位；可选缺失可正常展示；文本不影响关键操作 |
| AC-20 | 从不同工作目录、含空格路径启动 | 配置与日志路径正确，程序能够运行 |
| AC-21 | 从实际 TopSolid 入口启动并关闭窗口 | 入口步骤可复现，TopSolid 继续正常运行，当前 CAD 文档无变化 |
| AC-22 | 请求进行中关闭窗口 | 后台请求取消，退出不触发未处理异常，不影响 TopSolid |
| AC-23 | 在约定分辨率与 100%、150% DPI 下操作 | 核心字段和关键操作可用，无严重遮挡或不可达控件 |
| AC-24 | 核验数据访问范围 | 管理员确认目标用户可以读取连接身份可见的数据；有权限差异时按已确定方案验证 |
| AC-25 | 检查接口调用与日志 | 仅有经确认的只读业务接口调用；无文件内容下载、CAD 调用或业务写入；日志和包中无凭据 |

真实测试数据建议包括：足以跨两页的产品、无图纸产品、多附件产品、足以跨两批的关联图纸，以及可选字段缺失样例。禁止为了测试方便在生产环境随意新增或修改业务数据；可以使用已有记录、脱敏样例或专用测试环境。

交付时逐项记录通过、失败、未验证及原因。任何未完成的真实连接、Windows 运行或 TopSolid 入口测试都必须明确保留为未验证，不能用工程已生成代替验收通过。

## 十四、开发原则

1. 先完成第一阶段真实只读浏览，再进入第二阶段 CAD 协同。
2. 以已有明道云结构为准，不为插件新建重复业务数据。
3. 先验证真实接口和 TopSolid 接入能力，再承诺对应兼容性。
4. API、字段映射、ViewModel 与 UI 分层，但不为远期需求创建空抽象。
5. 以最小且聚焦的实现满足当前验收，注释解释必要的前提和边界。
6. 接口失败、没有数据、没有权限、只加载了一部分必须明确区分。
7. 所有进度报告区分样例验证、真实联调和 Windows/TopSolid 验证。

当前最优先工作是：确认真实产品表、图纸关系与只读身份，建立 WPF 工程并跑通真实查询；同时完成目标 TopSolid 版本的外部启动验证。
